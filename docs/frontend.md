# Frontend: общий бесконечный холст, MVP

Рабочее ТЗ для frontend-разработчика.

- Источник: [`shared-infinite-canvas-mvp-spec.docx`](../shared-infinite-canvas-mvp-spec.docx), версия 1.0 от 16.11.2026.
- Смежные документы: [backend](backend.md), [общий контракт v1](protocol.md).
- Требования исходника обязательны. Дополнения к неполному wire-контракту помечены в `protocol.md` как предложения для согласования.

## 1. Результат и границы ответственности

Сделать публичное desktop-приложение: один белый полноэкранный холст, где посетитель без регистрации рисует, перемещает камеру, видит завершённые штрихи других людей и удаляет только собственные штрихи текущей сессии.

**Стек:** Vite + TypeScript + Canvas 2D. Без React/Next.js и UI-фреймворка без необходимости. Один WebSocket на вкладку. Сервер раздаёт production-сборку приложения.

Frontend отвечает за ввод, отрисовку, камеру, палитру, локальное состояние, кеш видимой области, WebSocket-клиент, восстановление соединения и UI-тесты. Backend отвечает за хранение, валидацию, авторизацию удаления, серверный порядок и надёжную доставку снимка с изменениями.

**Изменение владельца (16.11.2026):** ограниченный зум 25–400% (17.11.2026 нижняя граница опущена до 16%) и touch/Apple Pencil (iPhone/iPad) реализованы во frontend, см. `../endless-drawing-frontend/README.md`. Серверный контракт не меняется: зум только клиентский, подписка по-прежнему в мировых единицах и не шире `VIEWPORT_MAX_SPAN`.

**Не делать в MVP:** аккаунты, комнаты, профили, ленты, чат, текст, вложения, экспорт, поиск координат, redo, курсоры других людей, передачу незавершённых штрихов, дополнительные страницы и админ-панель.

## 2. Интерфейс

- Обычное состояние — только белый холст на всё окно, без заголовков, постоянных панелей и видимой навигации.
- Правый клик открывает компактную палитру у курсора; нативное контекстное меню внутри холста отключено.
- Палитра не выходит за границы окна. Закрытие: Escape, клик снаружи, выбор инструмента.
- Инструменты: **Кисть / Рука / Ластик**.
- Настройки кисти: `round` / `square`, толщина `[1, 64]`, цвет `#RRGGBB`, непрозрачность `(0, 1]`.
- Переключение на руку/ластик не сбрасывает настройки кисти.
- При первом запуске активна кисть; далее инструмент восстанавливается из `localStorage`. Другие настройки также можно хранить там.
- Все элементы палитры доступны мышью и клавиатурой; фокус видим. Горячие клавиши холста не должны мешать вводу в полях палитры.
- Ошибки сети/сохранения показывать ненавязчиво, без постоянной панели.

Начальные цвет, толщина и opacity в исходнике не заданы; выбрать документированные значения, например `#202020`, `6`, `1`.

## 3. Управление

| Ввод | Поведение |
| --- | --- |
| Левая кнопка + кисть | Рисовать до `pointerup` |
| Левая кнопка + рука | Перетаскивать камеру |
| Левая кнопка + ластик | Удалить один собственный штрих под курсором |
| Средняя кнопка | Временно панорамировать независимо от инструмента |
| Space + левая кнопка | Временно панорамировать независимо от инструмента |
| Wheel / двухосевая прокрутка | Панорамировать по `deltaX`, `deltaY`; Ctrl/⌘+wheel и pinch — зум 16–400% |
| Правая кнопка | Открыть палитру |
| Ctrl/Cmd+Z | Удалить последний ещё существующий штрих сессии |
| Escape | Закрыть палитру / отменить незавершённый жест |

Подавлять стандартную прокрутку страницы и автопрокрутку средней кнопкой там, где ввод обрабатывает холст. Учитывать `WheelEvent.deltaMode`.

### Жест рисования

1. На `pointerdown` зафиксировать параметры кисти, начать локальный preview и захватить указатель.
2. На движении собирать мировые точки, прореживать избыточные события без заметного изменения формы.
3. Показывать preview сразу, не ожидая сервера; другим посетителям он не передаётся.
4. На `pointerup` отправить один `stroke.create` с новым UUID. Одиночный клик — штрих из одной точки.
5. `pointercancel`, потеря окна или Escape отменяют незавершённый штрих без отправки. Обработать потерю захвата и сброс временных модификаторов.
6. После подтверждения заменить pending-объект серверной записью, а не добавлять второй штрих.

Локальный неподтверждённый штрих и подтверждённый объект должны различаться в модели данных. Pending-объекты не входят в постоянный undo-стек.

## 4. Камера и координаты

Мировые координаты общие, тип — JS `number`, допустимы только конечные значения в `[-1_000_000_000, 1_000_000_000]`.

При новой независимой сессии центр камеры — `hello.ack.spawn`, если сервер его прислал и пользователь ещё не сдвинул камеру; иначе по каждой оси случайное значение в `[-250, 250]`. При перезагрузке вкладки восстанавливать камеру из `sessionStorage`. Камера на сервер не отправляется и там не хранится.

Зум ограничен `[0.16, 4]` CSS-пикселя на мировую единицу (при 1 — **1 мировая единица = 1 CSS-пиксель**). Ширина кисти задаётся в мировых единицах; допуск ластика — 4 CSS px на экране. При 16% окно шире ~4800 CSS px видит больше `VIEWPORT_MAX_SPAN` (30000): клиент подписывается на центральные 30000 по оси и не переподписывается из-за этого; лимит сервера не меняется.

```text
screenX = (worldX - cameraX) * zoom + viewportWidth / 2
screenY = (worldY - cameraY) * zoom + viewportHeight / 2
worldX  = screenX + cameraX - viewportWidth / 2
worldY  = screenY + cameraY - viewportHeight / 2
```

- `viewportWidth/Height` и координаты ввода здесь в CSS-пикселях.
- Физический размер backing canvas учитывать через `devicePixelRatio`; масштабировать контекст, не мировые данные.
- Resize/DPR change не меняет координаты сохранённых точек. Центр камеры сохраняется.
- Ограничивать камеру и bounds допустимым диапазоном. Не создавать canvas размером с мир.

## 5. Отрисовка

- Хранить векторы; canvas — только представление.
- Подтверждённые штрихи сортировать по серверному `seq` по возрастанию, а не по времени прихода.
- Фон белый, композиция `source-over`, opacity относится к целому штриху.
- `round`: округлённые концы и соединения; одиночная точка — круг диаметром `width`.
- `square`: квадратные концы и неокруглённые соединения без острых выбросов; одиночная точка — квадрат со стороной `width`.
- Использовать один алгоритм во всех поддерживаемых браузерах. Предлагаемая конкретизация Canvas-стилей и нюанс bounds описаны в [контракте](protocol.md#8-предлагаемые-геометрические-договорённости).
- Не наносить opacity повторно на пересечения примитивов одного штриха: если штрих собирается из отдельных фигур, при необходимости сначала собирать его непрозрачную маску, затем композить целиком.
- Перерисовывать через `requestAnimationFrame` только при изменениях: камера, preview, набор штрихов, resize и другие визуальные изменения.
- Допустимо кеширование неподвижной сцены; источником истины остаётся векторная модель.

## 6. Сессия, ластик и undo

### Анонимная сессия

- При отсутствии секрета создать 32 случайных байта через Web Crypto, закодировать в base64url и сохранить в `sessionStorage`.
- При каждом соединении передавать секрет только в `hello` по WSS. Не помещать его в URL, логи, `localStorage` или публичные объекты.
- При reload сохраняются секрет, камера и undo-стек. После утраты секрета право удаления прежних штрихов теряется.
- Дублирование/восстановление вкладки может копировать `sessionStorage`: нельзя обещать пользователю, что закрытие вкладки гарантированно отзывает право удаления.

### Ластик

- Искать только среди подтверждённых объектов с `own: true`.
- Hit-test учитывает толщину, форму кисти и небольшой допуск в экранных пикселях. Значение допуска документировать.
- При нескольких попаданиях выбирать **наибольший `seq`**, а не ближайший центр линии.
- Один клик удаляет целый один штрих; нет подходящих — ничего не происходит.
- Не рисовать белым и не вырезать фрагменты.
- Удаление выполняется через `stroke.delete`; окончательное право проверяет сервер. Не считать локальный `own` авторизацией.

### Undo

- Стек успешно созданных `id` хранится в `sessionStorage` в порядке успешного создания.
- Ctrl/Cmd+Z выбирает последний ещё не удалённый штрих, даже если он уже вне текущего viewport/кеша.
- Ластик, события удаления и результат запроса обновляют состояние стека; отсутствие объекта в кеше не означает его удаление.
- На время запроса защищаться от повторного удаления одного и того же элемента.
- Повторное удаление ранее удалённого своего объекта безопасно; при таком ответе продолжить поиск следующего при следующем undo.
- Redo отсутствует.

## 7. Загрузка, кеш и синхронизация

Использовать [протокол v1](protocol.md). Основной путь загрузки — WS snapshot; отдельный HTTP-клиент выборки не нужен.

### Область

Вычислить видимый мировой прямоугольник и добавить **по одному экрану в каждую сторону**. Итоговый prefetch-прямоугольник примерно `3 × viewportWidth` на `3 × viewportHeight`.

При панорамировании обновлять подписку с новым `subscription_id`. Допустим debounce/throttle, если пользователь не остаётся надолго с незагруженной видимой областью.

### Состояние клиента

Рекомендуется разделить:

- текущую камеру и инструмент;
- preview и pending-мутации;
- подтверждённые штрихи `Map<id, Stroke>`;
- набор объектов текущего snapshot;
- активный `subscription_id` и состояние соединения;
- undo-стек, отдельный от ограниченного кеша геометрии.

Snapshot может состоять из многих chunks, в том числе в плотной области. Дождаться `snapshot.end`; не считать первый chunk полной областью. Повторные объекты дедуплицировать по `id`.

Игнорировать сообщения старого `subscription_id`. На окончании нового snapshot считать его авторитетным для загруженной области: прежний кеш не должен сохранять удалённые за время отключения объекты. Практичный вариант — staging-набор с заменой активной сцены на `snapshot.end`, затем применение буферизированных сервером событий.

Недавние области можно кешировать, но ограничить кеш и вытеснять дальние. После реконнекта старый кеш нельзя считать актуальным без повторной загрузки. События удаления и ack должны снимать pending-объекты/обновлять кеш идемпотентно.

### Подтверждения и сбои

- Сопоставлять `ack`/`error` по `request_id`.
- Ack приходит автору и для штриха вне его подписки; не полагаться только на broadcast.
- Ack и `stroke.created` могут описывать один объект — отображать один раз, undo пополнять один раз.
- Потеря ответа не доказывает неуспешное сохранение. При повторе использовать **тот же UUID и то же содержимое**, а не создавать новый штрих.
- При реконнекте: `hello` → подтверждение → новая подписка → новый snapshot.
- Не обещать сохранение неподтверждённых штрихов; показать ненавязчивую ошибку и возможность повтора. Подтверждённые штрихи не теряются из-за разрыва сети.
- При `resync_required` или рассинхронизации запросить новый snapshot, а не пытаться восстановиться по `seq`: это порядок штрихов, не журнал удалений.

## 8. План работы без ожидания backend

1. Создать Vite/TypeScript-приложение; canvas, DPR/resize, камеру и локальное рисование.
2. Сделать палитру, инструменты, отмену жеста и единый renderer.
3. Выделить транспорт за интерфейсом, сделать mock WS по `protocol.md`: hello, многочастный snapshot, create/delete, ack/error.
4. Реализовать сессию, кеш, pending, ластик, undo, reconnect; проверить на mock.
5. Подключить реальный `/ws`, прогнать тесты с двумя независимыми браузерными контекстами.

Исходник предлагает монорепозиторий `frontend/`, `backend/`, `migrations/`. Сейчас Rust-пакет находится в корне репозитория: перенос согласовать, не делать его неявным условием интеграции. Frontend можно начать в `frontend/` независимо. Для dev согласовать proxy Vite → backend для `/ws` и health endpoints; production работает с одним origin.

## 9. Тесты и готовность

### Unit / component

- Обратимость world ↔ screen, панорамирование, resize и DPR.
- Сохранение камеры и инструмента, восстановление сессии.
- Одиночная точка, round/square, opacity, отмена незавершённого жеста.
- Hit-test: толщина, допуск, чужие штрихи, выбор максимального `seq`.
- Undo после reload, удаления ластиком и вытеснения геометрии из кеша.
- Дедупликация ack/event, chunks, игнорирование старой подписки, новая сцена после resync.

### Интеграционные / E2E

- Два независимых контекста видят один завершённый штрих без перезагрузки.
- Чужой штрих нельзя удалить; собственный удаляется целиком у обоих посетителей.
- Reload сохраняет рисунок, камеру и возможность удалить своё.
- Новая независимая сессия стартует возле `(0, 0)` со случайным сдвигом.
- Рука, Space+drag, средняя кнопка и wheel меняют камеру, не геометрию.
- Далёкое панорамирование загружает область порциями, не весь мир.
- Толстые штрихи у границы области не пропадают; наложения с opacity имеют одинаковый порядок в двух браузерах.
- Отключение во время create/snapshot, повтор UUID, удаление во время snapshot не дают дублей или пропусков.

Соответствие исходным критериям: AC-01–AC-12; AC-13 совместно с backend. Полные эксплуатационные проверки AC-14 — зона backend/DevOps.

**Передать:** исходники, команды dev/build/test, тесты, список поддерживаемых desktop-браузеров, описание хранилищ/кеша и transport mock. Production-сборка должна раздаваться backend без платных внешних сервисов.
